# Project Context Loader

本 skill 帮助 Agent 快速理解项目上下文，确保开发符合项目规范。

## 核心流程

### 阶段 1：检查项目规范文档

首先检查 `/AGENTS.md` 是否存在：
- **存在**：读取并遵循其中的规范
- **不存在**：进入阶段 2，生成项目规范文档

### 阶段 2：生成 AGENTS.md（如需要）

如 AGENTS.md 不存在，按照 [`references/generate-agents-guide.md`](./references/generate-agents-guide.md) 的步骤生成项目规范文档。

### 阶段 3：执行用户任务

根据用户请求执行相应操作：

#### 场景 A：了解项目
- 基于 AGENTS.md 提供项目概述
- 回答用户关于架构、原理的具体问题
- 指出关键代码位置和文件

#### 场景 B：开发新功能

**Step 1: 需求分析**
- 理解用户需求的完整上下文
- 识别需要修改的模块
- 评估对现有功能的影响

**Step 2: 方案设计**（遵循最小路径原则）
- 如无必要，勿增实体
- 优先复用现有代码
- 避免过度设计
- 第一性原理思考：这个功能的核心是什么？最简单的实现方式是什么？

**Step 3: 编码实现**
- 遵循 AGENTS.md 中的代码规范
- 保持与现有代码风格一致
- 在关键位置添加必要注释

**Step 4: 添加测试**
- 为新功能添加集成测试
- 测试用例不影响功能实现方式
- 测试覆盖正常路径和边界情况

**Step 5: 运行测试**
- 执行测试用例
- 修复失败的测试
- 确保所有用例通过

**Step 6: 更新文档**
- 同步修改到 README.md
- 如 API 变更，更新相关文档

**Step 7: 代码审查自检**
- 检查是否影响已有功能
- 检查代码风格一致性
- 检查测试完整性

## 关键原则

1. **最小路径原则**：新功能实现选择最简单、最直接的路径
2. **第一性原则**：回归问题本质，避免过度工程化
3. **如无必要，勿增实体**：不添加不必要的抽象、配置或依赖
4. **测试先行**：新功能必须有测试覆盖，但测试不扭曲实现
5. **文档同步**：代码变更必须同步到文档

## 注意事项

- AGENTS.md 的变更必须经过用户确认
- 不要在没有测试的情况下标记任务完成
- 修改前始终考虑对现有功能的影响
- 保持代码变更最小化，聚焦当前任务
